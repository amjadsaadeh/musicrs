# CLAUDE.md

## Project Overview

**musicrs** is a Rust port of the MUSIC (MUltiple SIgnal Classification) algorithm for Direction-of-Arrival (DOA) estimation with microphone/antenna arrays. Based on R. O. Schmidt's 1986 algorithm and the Python pyMUSIC implementation.

## Commands

```bash
# Build
cargo build
cargo build --release

# Test
cargo test              # all tests except slow ones (#[ignore = "slow"])
cargo test -- --include-ignored   # full suite, including slow tests (CI runs this)
cargo test --lib        # unit tests only
cargo test --test '*'   # integration tests only
cargo test --test golden_test   # parity with the original pyMUSIC spectra
cargo clippy --all-targets -- -D warnings   # CI runs this and `cargo fmt --check`
cargo audit             # RustSec advisories in Cargo.lock (CI runs this; install cargo-audit first)

# Documentation
cargo doc --open
```

## Architecture

```
src/
├── lib.rs      # Public API exports and crate-level docs
├── error.rs    # MusicError (returned by every fallible public function) and `musicrs::error::Result` (not re-exported at the root)
├── music.rs    # Core MUSIC algorithm (MusicEstimator, spectrum, DOA estimation)
└── stft.rs     # Signal processing (STFT, analytic signal via Hilbert transform)
tests/
├── common/mod.rs                # Shared WAV/filename/angle helpers, ErrorLog
├── integration_test.rs          # Narrowband DOA on every WAV recording (±0.5°)
├── ifb_test.rs                  # IFB-MUSIC on the tone's bin (nfft 160), below Nyquist (±0.5°); repeated and reordered bins
├── errors_test.rs               # Every MusicError the public API returns
├── golden_test.rs               # Spectra vs. pyMUSIC (incl. partial interval, 2 sources narrowband and IFB, nfft 320/1024); analytic signal vs. scipy; musicrs snapshots at/above Nyquist
├── broadband_test.rs            # IFB-MUSIC on composite multi-tone signals; two sources at different angles
├── noisy_data_test.rs           # Narrowband and IFB (energy-selected bins) DOA with added white noise
├── synthetic_test.rs            # Synthetic plane waves: 2-D arrays, 2–3 sources, coherent sources (not resolved), endfire, edge cases, 48 kHz
├── golden/                      # pyMUSIC reference CSVs, *.musicrs.csv snapshots, generate_golden.py
└── data/single-source/*.wav     # 4-channel 24-bit 16kHz test recordings
examples/bench_pymusic.rs        # musicrs side of the runtime benchmark vs pyMUSIC
bench/                           # pyMUSIC and vectorized-numpy harnesses, analyze.py (stats + charts), results/; see bench/README.md
docs/benchmark*.svg              # charts shown in the README (light and dark), generated by bench/analyze.py
```

**Key types:**
- `MusicEstimator` — main struct; configure antenna positions, angle search range/step, sample rate, and number of sources
- `MusicEstimator::estimate_doa_from_real()` — real-data entry point (removes each channel's mean, then the covariance of the analytic signals, eigendecomposition, spectrum and peaks as in `estimate_doa`, without calling it), like pyMUSIC's `getSourceAngles`. It never forms the analytic signals: their covariance comes from each channel's real FFT by Parseval (`analytic_covariance`), with real FFT plans cached per thread (`stft::real_fft_plan`). The golden/snapshot spectrum tests build their covariance with `analytic_signal` instead, so they do not cover this path; only the DOA-level tests do
- `MusicEstimator::ifb_music_spectrum()` — wideband variant; bin frequencies use the estimator's `sample_rate`, so tones above Nyquist cannot be recovered
- `select_bins_by_energy()` — picks the IFB bins within N dB of the strongest; with `bins = None` noise-only bins dominate the geometric mean
- `analytic_signal()` — converts real signal to complex via Hilbert transform (FFT-based)
- `stft()` — Short-Time Fourier Transform with configurable window and overlap

- `MusicError` — bad data (wrong row count or covariance shape, no samples, NaN/inf, silence) and bad parameters (too many or zero sources, angle grid incl. spans over 2π, frequency ≤ 0 or non-finite, sample rate, antenna positions, `nfft`, overlap, threshold, no usable bins) are returned as `Err`; the public API does not panic on them and does not return a quiet wrong answer. The estimator's fields are checked where they are used, not in `new()`, because the fields are public. `noise_subspace` reads only the lower triangle of `cov`; IFB never uses the DC bin

**Core algorithm flow:**
1. Compute covariance matrix of complex multichannel input
2. Hermitian eigendecomposition (`faer`) → signal/noise subspace split
3. Compute MUSIC pseudo-spectrum using steering vectors
4. Peak detection → DOA estimates in radians

## Testing

Integration tests load WAV files from `tests/data/single-source/` and compare DOA estimates with the ground truth in the file name. Clean recordings land exactly on the true angle, so their tolerance is one 0.5° grid step; noisy and broadband-triple tests use tolerances set a little above the measured worst error. `common::ErrorLog` prints the worst error per test (`cargo test -- --nocapture`), which is the number to re-check before changing a tolerance. File naming convention:

```
single-source_<freq>Hz_<doa>deg_<duration>s.wav
```

Test data covers:
- Frequencies: 300 Hz – 9.1 kHz (in ~1.1 kHz steps)
- Angles: 0°, 40°, 80°, 120°, 160°
- Durations: 1 s and 2 s
- Array: Kinect 4-mic geometry

## Workflow

- Before implementing a non-trivial change, propose a plan and get it approved first. While planning, ask clarifying questions about anything ambiguous (scope, API shape, defaults, test data) rather than guessing.

- Make changes on a branch, never directly on `main`:
  - `feat/<feature-name>` for new features
  - `fix/<bugfix-name>` for bug fixes
- Structure work in reasonably sized commits: each commit is one logical change that builds and passes tests on its own.
- A project Stop hook (`.claude/settings.json` → `.claude/hooks/run-tests.sh`) runs `cargo test` when a turn ends with changed code under `src/`, `tests/` or `Cargo.*`, and sends failures back to Claude. Tests that take more than ~10 s are marked `#[ignore = "slow"]`, so the hook skips them; run `cargo test -- --include-ignored` for the full suite. Set `MUSICRS_SKIP_HOOK_TESTS=1` before starting Claude Code to turn the hook off.
- Parallel builds (subagents in separate worktrees, or a second `cargo test` next to the Stop hook) must not share a Cargo target directory. Worktrees of this crate produce the same test-binary paths (e.g. `target/debug/deps/noisy_data_test-<hash>`), and cargo releases its build lock before running the tests, so one run can execute another worktree's binary: tests go missing or fail on code that isn't there, or a binary being rewritten fails with "Permission denied". Give each worktree its own `CARGO_TARGET_DIR` (on this 3-core machine also `CARGO_BUILD_JOBS=1`), and check that new tests appear by name in the output before trusting a run.

## Notes

- Rust edition 2024; `rust-version` in `Cargo.toml` (1.89, set by `nalgebra` 0.35) is the lowest Rust the crate builds with. Raise it when code or a dependency update needs a newer Rust
- No `rustfmt.toml` or `clippy.toml` — use `cargo fmt` and `cargo clippy` defaults
- Golden files: `*.eigh.csv` (pyMUSIC with `np.linalg.eigh`) and `*.hilbert_n<N>.scipy.csv` (`scipy.signal.hilbert`) must match value-by-value; `*.eig.csv` (pyMUSIC as published) only by peak location, because `np.linalg.eig` returns a non-orthogonal noise basis on this near-noiseless data. Regenerate with the command in `tests/golden/generate_golden.py`.
- Snapshot files: `*.narrowband.musicrs.csv` in `tests/golden/` are musicrs's own narrowband spectra at and above Nyquist (8000 Hz, 9100 Hz), not pyMUSIC references (musicrs deliberately differs from pyMUSIC there). They pin the at/above-Nyquist steering-vector behaviour: `1 / spectrum` (the MUSIC denominator) must match to 1e-9 of its maximum and the peak must not move. The spectrum itself is not compared relatively, because at the peaks its denominator is at rounding level and moves with the eigensolver. After an intended change, regenerate with `MUSICRS_UPDATE_SNAPSHOTS=1 cargo test --test golden_test` and review the diff.
- Sign convention: musicrs uses a non-conjugated analytic signal with an `exp(+j2πfτ)` steering vector; pyMUSIC conjugates the analytic signal and uses `exp(−j2πfτ)`. Equivalent below Nyquist. The above-Nyquist sign flip and the real steering vector at Nyquist are musicrs additions tuned to the test data.
